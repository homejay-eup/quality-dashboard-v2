# SOP／環境與版控

> 主 `CLAUDE.md` 只在「觸發時」指你來讀這份。平常不載入，省 context。
> 四種觸發情境：①開案初始化（版控規範）②開案後設定技術棧 MCP ③工具失效需降級 ④維護原則四閘門 hook。

---

## 一、開案初始化：版本控制規範

### 新專案初始化必做
0. **先 `rm -rf .git`**——範本是整包複製過來的，會帶著範本自己的 commit 歷史與分支，新專案不該繼承（PowerShell：`Remove-Item -Recurse -Force .git`）
1. `git init`（框架腳手架通常自動建立，確認即可；可用 `git init -b main`）
2. **`.gitignore`：範本已內附一份**（含機密／依賴／建置產出／測試產出／Claude Code／CodeGraph 索引／系統 IDE）。依 STACK_RULES 在末段「專案自訂」追加技術棧特有排除；**若檔案不存在則依本節建立，不可略過**
3. `git status` 確認機密檔（`.env*`、`_secrets/`）**沒有出現在待追蹤清單**後，才執行第一次 commit

### 應 commit（初始化 commit 必須包含）
```
CLAUDE.md  README_範本使用說明.md  .claude/  .mcp.json  .gitignore
_管理/  _開發檔案/  .github/  playwright.config.ts  程式碼目錄  技術棧設定檔
```
> ⚠️ **`.github/` 與 `playwright.config.ts` 必須進 repo**，否則 CI（push main 自動跑 Playwright）**永遠不會啟用**，而文件卻宣稱它在保護 main。
> ⚠️ **`.mcp.json` 必須進 repo**，否則 CodeGraph MCP 不會被載入（見第二節）。

### 不追蹤（已寫入範本 `.gitignore`）
機密（`.env*`，`.env.example` 例外保留／`_secrets/`）、依賴目錄（`node_modules/`／`.venv/`）、建置產出（`.next/`／`dist/`）、測試產出（`test-results/`／`playwright-report/`）、`.claude/worktrees/`、`.claude/settings.local.json`、**`_管理/.verify-marker`／`_管理/verify-bypass.log`**（原則四閘門的執行期產物）、**`_管理/任務報告/全分支diff.txt`**（審查暫存，與 git 歷史重複）、`.codegraph/`、系統與 IDE 檔。

> 🔴 **改 `.gitignore` 的必知陷阱**：**不支援行尾註解**——`#` 只有在行首才是註解。寫成 `.claude/worktrees/    # 說明` 會讓整串變成字面 pattern 而**完全失效**。
> 改完請實測：`git check-ignore -v -- <該路徑>`，有輸出才代表規則生效。

## 二、MCP 設定位置與依技術棧追加

### ⚠️ 設定位置（**專案層 MCP 只認 `.mcp.json`**）

| 設定檔 | 作用 |
|---|---|
| **`.mcp.json`（專案根目錄）** | **定義**專案層 MCP server ← 範本的 CodeGraph 寫在這裡，追加 MCP 也加在這裡 |
| `.claude/settings.json` | Hooks、`enableAllProjectMcpServers`（自動核准 `.mcp.json` 的 server）等設定。**`mcpServers` 不是有效的 settings.json 鍵**，寫在這裡不會生效 |

> ⚠️ `.claude/settings.json` 的 `mcpServers` 鍵不被讀取，CodeGraph 必須寫在專案根目錄 `.mcp.json` 才會生效。
> **驗證方式**：在專案內輸入 `/mcp`，codegraph 應出現在清單中。

### 依技術棧追加的 MCP（加到 `.mcp.json` 的 `mcpServers`）

**開案時依 STACK_RULES 判斷需要哪些並加入**；範本預設只含 CodeGraph（RTK 走 hook 不是 MCP）：

| MCP | 主要使用者 | 用途 | 適用棧 |
|---|---|---|---|
| Supabase | `data` | 執行 SQL、查 schema、產型別（⚠️ 只連 dev project）| Supabase |
| Context7 | `frontend` / `data` | 即時拉版本文件，防廢棄 API 幻覺 | 多數 JS/TS 棧 |
| Playwright | `tester` | 操作瀏覽器驗證 UI 行為（MCP 即時 + 腳本回歸兩模式）| Web 前端 |
| Vercel | 主 Agent | 查部署、build/runtime log、env | Vercel 部署 |

> ⚠️ **加完 Playwright MCP 後**：確認 `tester.md` frontmatter 的工具白名單涵蓋實際的工具名稱前綴（以 `.mcp.json` 安裝為 `mcp__playwright__*`，以 plugin 安裝為 `mcp__plugin_playwright_playwright__*`）。**白名單對不上時 tester 會靜默走降級路線**（只寫腳本不即時驗收）。

### 環境變數與金鑰隔離（通用規則，不限特定服務）

任何串接第三方服務的金鑰／連線字串（資料庫、金流、email/簡訊/推播、外部 AI API），STACK_RULES 建檔時必須註明 **dev/test/prod 各自的取得方式**。

🔴 **agent 執行任何會產生真實副作用的操作前**（送出 API 請求、跑 migration、發送通知、扣款），若無法從當下 context 判斷目前使用的是哪個環境的金鑰，**停下回報，不假設是安全的**（屬 `CLAUDE.md`「決策分級判準」紅線類別之一，判準單一來源見該節）。這條規則涵蓋所有服務，不需要每加一個新服務就補一條——新增技術棧時只需在 STACK_RULES 註明對應服務的 dev/test 金鑰位置。

> 已知個案：Supabase MCP 只連 dev project（見上表）；`data.md` 要求 DB 連線模組支援測試模式切換（見該檔）——兩者都是本條通用規則的具體實例。

### 非 MCP 的兩項工具（不寫在 `.mcp.json`）

| 工具 | 怎麼啟用 |
|---|---|
| **Chrome 整合** | 不是 MCP。需安裝 [Claude in Chrome 擴充套件](https://chromewebstore.google.com/detail/claude/fcoeoabgfenejglbffodgkkbkcdhcgfn)，啟動加 `--chrome` flag 或 session 內輸入 `/chrome` |
| **GitHub Actions CI** | 不是 MCP。範本已附 `.github/workflows/test.yml`（push／PR main 自動跑 typecheck → unit test → build → Playwright；typecheck 與 unit test 用 `--if-present`，沒有對應 npm script 就自動略過，指令依 STACK_RULES 調整）——**只要確保該檔進了 repo 即生效**（見第一節應 commit 清單）。⚠️ **從首次 commit 到專案骨架建好（有 `package.json`）、且 `playwright.config.ts` 的 `webServer` 補上之前，CI 會紅，屬正常**——骨架完成後轉綠 |

## 三、工具降級方案

工具無法執行時按下表降級，**核心邏輯不受影響，只影響效率**：

| 工具不可用 | 降級做法 | 效率影響 |
|---|---|---|
| RTK | 直接執行 Bash，手動監控 context，拆任務更保守 | token 節省失效 |
| CodeGraph | 改用 Grep 查依賴 | 依賴查詢變慢 |
| Supabase MCP | 產 SQL 後告知使用者手動在 Dashboard 執行 | 需人工介入 |
| Context7 | 依訓練資料，遇 API 問題手動查官方文件 | 廢棄 API 風險上升 |
| Playwright MCP | 改寫測試腳本手動執行（`npx playwright test`）| 無法即時瀏覽器驗證，仍有腳本回歸保護 |
| Chrome 整合 | 改用 Playwright MCP 或手動開瀏覽器 | Chrome 整合未安裝時退回 Playwright |
| Vercel MCP | 開瀏覽器進 Dashboard | 需切換視窗 |

## 四、原則四閘門（hook）維護須知

> ⚠️ **閘門僅 Windows PowerShell 生效**。Mac／Linux／WSL 環境三支 hook 全部不執行、且 fail-open 靜默——需人工在 commit 前確認驗證已跑、push 前確認已獲授權。bash 版待補。

閘門由兩支腳本組成，設定於 `.claude/settings.json`：

| 腳本 | 事件 | 作用 |
|---|---|---|
| `_開發檔案/scripts/hooks/mark-verify.ps1` | PostToolUse (Bash) | 偵測到驗證類指令 → 寫 `_管理/.verify-marker` |
| `_開發檔案/scripts/hooks/verify-gate.ps1` | PreToolUse (Bash) | `git commit` 前檢查標記是否比最新 staged 程式碼檔更新；並攔截 `git push` |

### 🔴 改這兩支腳本時的必知陷阱

1. **必須存成 UTF-8 with BOM**。Windows PowerShell 5.1 讀 `.ps1` 預設用 ANSI，**UTF-8 無 BOM 的中文會變亂碼並造成解析失敗**（腳本整個不執行 → 閘門靜默失效）。用一般編輯器存檔後請確認 BOM：
   ```powershell
   $p = "_開發檔案\scripts\hooks\verify-gate.ps1"
   $c = Get-Content -Raw -Encoding UTF8 $p
   [System.IO.File]::WriteAllText($p, $c, (New-Object System.Text.UTF8Encoding($true)))
   ```
2. **`[Console]::OutputEncoding` 必須設 UTF-8**（`verify-gate.ps1` 開頭已設）。否則 deny 訊息的中文在 stdout 會變亂碼，Claude 收到的是垃圾字元。
3. **新增技術棧要到 `mark-verify.ps1` 追加驗證指令 pattern**。沒加的話，該棧的測試跑了也不會被認可 → 每次 commit 都被擋（假警報）。
4. **`settings.json` 用 `$CLAUDE_PROJECT_DIR` 絕對路徑註冊**，腳本內也要 `Set-Location (git rev-parse --show-toplevel)`。相對路徑在 cwd 非專案根時（子目錄啟動／worktree／monorepo）會解析失敗 → **fail-open 靜默放行**。
5. **任何新增到 `_開發檔案/scripts/` 的含中文 `.ps1` 一律存 UTF-8 with BOM**（同上第 1 點的理由）。

### 已知的設計取捨（不是 bug）

| 行為 | 原因 |
|---|---|
| `npm run build && git commit` 連鎖指令被放行而非強制拆開 | PreToolUse 在整串執行**前**判斷，此時驗證尚未跑。閘門偵測到同串含驗證指令即放行；文件建議仍拆成兩次呼叫 |
| stage 之後又動工作區（reviewer 要求小修、IDE 自動格式化）導致 commit 被擋 | 閘門用 index 時間判斷已 stage 的快照，工作區有新變更時仍以保守為準。**正解是重跑驗證，不是加 `[skip-verify]`** |
| 豁免採**目錄級**（`_管理/`／`.claude/`／`.github/` 下一律放行）| 這些目錄在範本中只放文件與設定。**例外**：副檔名為 `.ps1/.sh/.py/.js/.ts` 等可執行腳本即使在豁免目錄下仍視為程式碼 |
| 每次 Bash 呼叫會啟動 **3 個 PowerShell 行程**（PreToolUse×2＋PostToolUse×1）| 單次約 100–200ms。可接受成本；若感到延遲，可停用 RTK hook 或把兩支 Pre hook 合併 |

### 改完必測（十一個情境）

改動後請實際驗證，**不要只看程式碼就宣稱可用**（那正是原則四要防的）：

| # | 情境 | 期望 |
|---|---|---|
| 1 | staged 只有 `.md` | 放行 |
| 2 | staged 含程式碼、無標記 | **擋下** |
| 3 | 跑過驗證後 commit | 放行 |
| 4 | 驗證後又改碼（嚴格模式） | **擋下** |
| 5 | commit message **第一行**含 `[skip-verify]`（如 `git commit -m "fix x [skip-verify]"`）| 放行 ＋ 留痕 |
| 6 | 非 commit 指令（如 `git status`） | 放行 |
| 7 | 腳本本身出錯／非 git repo | 放行（fail-open）|
| 8 | git 前面加了包裝指令前綴（如 `rtk proxy git commit`）| **verify-gate 依驗證狀態正常判斷**；**mark-verify 仍正確排除 git 指令本身**（不可因 commit message 含驗證字樣就誤寫標記）|
| 9 | commit message 的 **heredoc 內文**（非第一行）提到 `[skip-verify]`＋staged 含未驗證程式碼 | **擋下**（不可因內文提到 token 就當成使用逃生門）|
| 10 | `git push` 作為指令（行首或 `&&`／`;` 之後，含 `git -C p push`）| **擋下**（訊息要使用者自行執行）|
| 11 | commit message 內文提到「git push」字樣 | 放行（只認第一行的 git 子指令，不誤命中訊息）|

> ⚠️ **閘門只認指令第一行的 `[skip-verify]`**。多行 heredoc 訊息若真要用逃生門，把 `[skip-verify]` 放進 `-m` 的第一行。文件提到這個 token 時用反引號包起來（`` `[skip-verify]` ``）。

測法：建臨時 git repo，把 JSON 餵給腳本 stdin：
```powershell
'{"tool_name":"Bash","tool_input":{"command":"git commit -m \"x\""}}' | powershell -NoProfile -ExecutionPolicy Bypass -File "_開發檔案/scripts/hooks/verify-gate.ps1"
```
輸出含 `"deny"` ＝ 擋下；無輸出 ＝ 放行。

---

> ⚠️ **降級不影響四條核心原則的執行**：CodeGraph 掛了改用 Grep 查 import／usage（原則一仍要做）；Playwright MCP 掛了改跑腳本（原則四的驗證證據仍要貼實跑輸出）。**工具可以降級，原則不可以。**
