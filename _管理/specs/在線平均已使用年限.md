# 在線平均已使用年限 規格

## 這個功能做完，你會看到什麼

你打開儀表板時，KPI 卡區塊會多兩張卡片：「在線平均已使用年限（車機）」跟「在線平均
已使用年限（鏡頭）」，跟「總線上量」放在一起，可以照廠商/類型/ERP品號篩選，篩完數字
會跟著變。這兩張卡片不會跟著「本季/去年同期」變動（跟「總線上量」一樣是現在時點的
數字，不是本季的流量）。

第一次登入時，會多跳出一次 Google 同意畫面（因為要多一項讀取權限），點同意後，之後
大部分時候都感覺不到，跟現在一樣順。如果這個授權剛好出問題（網路、被拒絕、瀏覽器擋
彈窗），只有這兩張卡片會顯示「無法載入，點選重試」，其他 KPI、明細表、篩選都正常。

你按「📥 匯出本期快照」時，這份資料也會一併存進共用雲端硬碟，為未來能比較「去年同期」
累積歷史（這次不會出現「去年同期」的比較畫面，只是開始存資料）。

## 驗收條件

- [ ]（正常流程）登入後（含第一次多同意一次授權），KPI 卡區塊出現「在線平均已使用
  年限（車機）」「在線平均已使用年限（鏡頭）」兩張卡片，數字為對應設備類型的平均已
  使用年限
- [ ]（正常流程）依廠商/類型/ERP品號篩選後，這兩個數字會跟著重新計算
- [ ]（正常流程）這兩張卡片不隨「本季/去年同期」的期間選擇變動數字（跟「總線上量」
  行為一致，不顯示 delta 箭頭/對比數字）
- [ ]（正常流程）按「📥 匯出本期快照」後，共用雲端硬碟出現這份在線明細的快照檔
  （沿用既有 `App.cloud.snapshotSheet()`，Drive 對 Drive 複製，不經瀏覽器上傳）
- [ ]（錯誤情境）OAuth 授權失敗、被拒絕、或瀏覽器擋下同意彈窗 → 只有這兩張卡片顯示
  「無法載入，點選重試」，其他 KPI、明細表、篩選功能都正常運作；點「重試」會重新觸發
  授權（授權請求需綁在使用者的點擊事件上，不能在頁面載入時自動彈窗）
- [ ]（邊界條件）某條記錄「日期依據」欄指向的日期欄位剛好是空值 → 改用另一個日期欄位；
  兩個日期欄位都沒有值，或算出負值（資料異常）→ 該筆不計入平均，不讓整體計算出錯
- [ ]（邊界條件）篩選後沒有符合的設備，或設備都有但日期全部不可用（分母為 0）→ 兩種
  情況都顯示空白/「無資料」，不顯示 0
- [ ]（邊界條件）已登入使用者第一次操作到這個新功能時才跳出額外同意畫面（不是登入
  當下就跳兩次），之後同一瀏覽器內的授權能背景靜默換發，不需要每小時手動再點一次

## 🔧 開發區（非技術者可略過）

### 頁面 / 元件清單

- `js/auth.js`：現有 Google Sign-In（ID token）流程旁，新增 OAuth2 token client
  （`google.accounts.oauth2.initTokenClient`），scope
  `https://www.googleapis.com/auth/spreadsheets.readonly`；`requestAccessToken()`
  接在既有登入按鈕的同一個點擊回呼裡；已授權時用背景計時器在到期前用 `prompt: ''`
  主動換發
- `js/sheets.js`：新增讀取「車機鏡頭上線明細」的函式（呼叫 Sheets API v4
  `spreadsheets.values.get`，帶 Authorization Bearer token，只取需要的欄位範圍）
- `js/metrics.js`：新增計算函式（依規則 H，見下方「對應規則文件」），輸入這份新資料
  ＋現有 selection，輸出 `{ 在線平均已使用年限_車機, 在線平均已使用年限_鏡頭 }`
- `js/app.js`：
  - `METRICS` 陣列（約 18 行起）新增兩筆定義（`key`/`label`/`fmt: 'year'`/
    `better: null`/`get`）
  - `NO_DELTA_METRICS`（約 159 行）加入這兩個新 key，讓卡片不顯示期間 delta
    （跟現有 `總線上量` 的處理方式一致）
  - 需要一個載入失敗態的呈現（沿用 `kpi__empty` 樣式或新增對應 class），含「重試」
    按鈕，重試需重新觸發使用者手勢才能再跳 OAuth 同意畫面
- `js/report.js`：既有「📥 匯出本期快照」按鈕處理函式，多呼叫一次
  `App.cloud.snapshotSheet(新Sheet的ID, label)`（`js/cloud.js` 既有函式，不需修改
  `js/cloud.js` 本身）——**動手前先確認 Apps Script 部署者本身對這份私有 Sheet 有
  檢視權限**，否則 Drive 對 Drive 複製會失敗
- `設備品質分析_分冊文件/00_規則定義.md`：新增「規則 H：在線平均已使用年限」

### 欄位定義（新 Sheet「車機鏡頭上線明細」）

| 欄位名 | 型別 | 必填 | 說明 |
|---|---|---|---|
| 條碼 | string | 是 | 設備唯一識別碼 |
| 設備類型 | string | 是 | 本功能只處理「車機」「鏡頭」兩種值 |
| ERP品號 | string | 否 | 供廠商/類型篩選 join 用（同現有慣例）|
| 進貨日 | date string | 否 | 「日期依據」＝進貨日時的計算基準 |
| 安裝日 | date string | 否 | 「日期依據」＝安裝日時的計算基準 |
| 日期 | date string | 否 | 已依「日期依據」算好的參考日期（可直接採用，缺值時才退回自行判斷）|
| 日期依據 | string | 否 | 值為「進貨日」或「安裝日」，指出「日期」欄取哪一個 |

### 對應規則文件

`設備品質分析_分冊文件/00_規則定義.md` 新增規則 H：

- 計算對象：目前線上（新 Sheet 名單內）的車機／鏡頭，**不限**回廠或良品狀態
  （跟規則 E 的計算對象完全不同，不要混用）
- 計算公式：`(今天 − 參考日期) / 365`，取小數點第一位（沿用規則 E 既有公式）
- 參考日期：優先採用「日期」欄；缺值時依「日期依據」欄指向的欄位取值，該欄也缺
  時改試另一欄；兩欄都無值，或算出負值，皆視為不可用、不計入平均
- 車機／鏡頭分別獨立取平均，不合併

### 流程說明

1. 使用者點登入按鈕 → 同一回呼內取得身份 token + Sheets 讀取授權（已授權過則靜默）
2. 呼叫 Sheets API 讀「車機鏡頭上線明細」
3. 依規則 H 算車機／鏡頭各自的在線平均已使用年限
4. 依目前篩選（廠商/類型/ERP品號）重新計算 → 顯示於 KPI 卡
5. 使用者按「匯出本期快照」時，額外呼叫一次 `snapshotSheet()` 存這份資料
