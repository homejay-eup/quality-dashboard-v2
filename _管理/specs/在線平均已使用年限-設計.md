# 設計文件：在線平均已使用年限

## 功能目標

現有「總線上量」KPI 只有數量，看不出這些還在線上的設備平均用了幾年。這次要新增一個
「在線平均已使用年限」指標，讓使用者知道目前線上車機/鏡頭的平均年齡，而不是只看
回廠、報修過的那一小群設備（現有「已使用年限」只算這群）。

## 你會看到什麼（白話）

你打開儀表板時，KPI 卡區塊會多一張「在線平均已使用年限」卡片，跟「總線上量」放在一起。
上面會顯示目前所有線上車機/鏡頭平均用了幾年，可以照廠商/類型/ERP品號篩選，篩完數字
會跟著變。如果這張卡片剛好抓不到資料（例如網路問題），只會有這一張卡片顯示「無法載入，
點選重試」，畫面其他部分（KPI、明細表、篩選）都正常，不受影響。

目前只會顯示「現在」這個時間點的數字，還不能跟「去年同期」比較——因為現有資料只有
「現在線上有哪些設備」的名單，沒有「去年這個時候線上是哪些設備」的歷史名單。從這次
上線後，你按「📥 匯出本期快照」時，這份在線明細也會一起存進共用雲端硬碟；累積夠幾季
之後，未來才能做同期比較（這次不做比較畫面，只是開始存資料）。

第一次使用這個新功能時，登入後會多跳出一個 Google 同意畫面（因為要多要一項讀取權限），
點同意後，之後大部分時候都不會再看到這個畫面。

## 範圍界定

**本次包含：**
- 新增「在線平均已使用年限」KPI 卡（車機/鏡頭），可依廠商/類型/ERP品號篩選
- 讀取新資料來源「車機鏡頭上線明細」（逐條碼進貨日/安裝日明細），改用 OAuth（沿用
  現有 Google 登入，擴增 Sheets 讀取授權）存取，因為該表目前設為需登入才能檢視
- OAuth 授權失敗時的局部退路（僅該 KPI 卡顯示錯誤＋重試，不影響其他畫面）
- 把「車機鏡頭上線明細」也接進既有「📥 匯出本期快照」的匯出動作（同一次點擊、多存一份
  資料），供未來累積歷史快照

**本次不包含：**
- 「去年同期」/歷史比較的**呈現畫面**（快照資料這次就開始真的存，但比較 UI 要等快照
  累積夠幾季後才做，不是本次範圍）
- 獨立的、不需要人手動點擊的自動排程（這次沿用「使用者按匯出按鈕才存」的既有模式，
  不新增背後自動執行的排程機制）
- 除車機/鏡頭以外的設備類型（新資料來源本身就只涵蓋這兩類，跟「總線上量」裡其他
  約 37 種配件類型無關，不強行擴大範圍）
- 修改「已使用年限」（規則E，回廠非良品桶）既有計算方式——兩者是完全不同的兩個指標，
  只是名稱相近，這次會用不同名稱區分，不會動到既有規則
- 改動 Google Sheet 本身的分享設定或內容（含清理那個無關的空分頁 `SQL_上線明細`）

## 技術方案

- **資料來源**：私有 Google Sheet「車機鏡頭上線明細」（單一分頁，逐條碼：條碼/設備
  類型/產品類別/ERP品號/品名/進貨日/安裝日/日期/日期依據/車代/客代/客戶名稱/機種）
- **存取方式**：`js/auth.js` 現有的 Google Identity Services「Sign In」流程（只給身份、
  不能呼叫 API）之外，另外用同一套 GIS 函式庫的 OAuth2 token client
  （`google.accounts.oauth2.initTokenClient`），額外要求
  `https://www.googleapis.com/auth/spreadsheets.readonly` 唯讀範圍，呼叫 Sheets API v4
  的 `values.get` 讀資料（只取需要的欄位範圍，如 `A:I`，不含客代/客戶名稱/機種，減少
  單次回應大小）。
  - ⚠️ **觸發時機**：跳出同意畫面的授權請求（`requestAccessToken()`）必須綁在使用者的
    點擊動作上，不能在畫面載入時自動呼叫，否則瀏覽器的彈出視窗封鎖機制會擋掉——實際
    做法是接在既有「Sign In With Google」按鈕的同一個點擊事件回呼裡，緊接著一起請求，
    使用者感覺是「登入」這一個動作，不是分成兩次點擊。
  - 已授權過的情況下，改用背景計時器在 token 到期前幾分鐘主動用 `prompt: ''` 換發新
    token（不是等呼叫 API 失敗才發現），使用者不會感覺到中斷。
- **已核對資料範圍一致**：這份新表格的總筆數（220,849）跟公開來源表「SQL_上線量」
  分頁車機（148,685）+鏡頭（72,164）加總完全一致——兩者是同一批設備，不需要處理
  兩份數字對不齊的情況。
- **計算方式**（沿用規則E既有公式，計算對象不同）：
  `(參考日期 − 進貨日/安裝日) / 365`，對這份名單裡「車機」與「鏡頭」設備類型**分別**取
  平均，取小數點第一位（KPI 卡分開顯示兩個數字，不合併，跟現有畫面拆車機/鏡頭頁籤的
  慣例一致）。
  - 「日期依據」欄已經幫每列決定好優先要用進貨日還是安裝日，優先採用該欄指向的日期；
    若那一欄剛好是空值，改試另一欄；兩欄都沒有值，或算出來的年限是負值（日期填反、
    資料異常），都視為不可用，比照 `transform.js` 現有 `calc已使用年限()` 的處理方式，
    不計入平均、不讓整體計算出錯。
  - 分母為 0（不論是篩選後沒有符合的設備、或是有設備但全部日期都不可用）時，KPI 卡
    一律顯示空白/「無資料」，不當成 0 年——跟「篩選後沒有符合的設備」共用同一套顯示。
- **命名**：UI 上顯示「在線平均已使用年限」，跟既有「已使用年限」（回廠非良品桶，
  規則E）用不同字樣區分，避免使用者誤以為是同一個數字。
- **需要新增到 `00_規則定義.md`**：建議新增「規則 H：在線平均已使用年限」記錄這條
  計算方式（呼應本專案「邏輯先寫文件、程式再照做」的既有慣例），不是技術選型變更，
  依 `CLAUDE.md` 判準屬於純內部實作手法，AI 自主決定即可，記錄於 `方案紀錄.md`。

## 主要流程

1. 使用者點「Sign In With Google」登入（既有登入閘），同一個點擊回呼裡緊接著一併請求
   Sheets 讀取授權（已授權過的回訪者，這步是背景靜默完成，不會多跳畫面）
2. 取得 token 後，呼叫 Sheets API 讀「車機鏡頭上線明細」（限縮欄位範圍）
3. 依「日期依據」欄挑可用的日期，算每列的已使用年限，依設備類型（車機/鏡頭）分組取平均
4. 依使用者目前的廠商/類型/ERP品號篩選重新計算（跟其他 KPI 卡篩選邏輯一致）
5. 顯示在「在線平均已使用年限」KPI 卡（車機/鏡頭各一個數字）；任一步驟失敗 → 只讓這張
   卡顯示錯誤＋重試按鈕
6. 使用者按「📥 匯出本期快照」時，這份在線明細資料也一併存進共用雲端硬碟（沿用既有
   Drive 對 Drive 複製機制），供未來累積歷史後做同期比較用

## 邊界條件與備援

- **OAuth 授權失敗／被拒絕／逾時／瀏覽器擋下同意彈窗**：KPI 卡顯示「無法載入，點選
  重試」，其他畫面正常；重試時使用者需要再點一次觸發（同上「觸發時機」說明）
- **某條記錄進貨日／安裝日都缺值，或算出負值年限**：該筆不計入平均，不會讓整體平均
  出錯或出現不合理的負數
- **篩選後沒有符合的設備，或設備都有但日期全部不可用**：KPI 卡一律顯示空白/「無資料」，
  不當成 0 年
- **這份 Sheet 之後又被改成公開連結／或改回需登入**：因為是走 OAuth 讀取（不是拼公開
  URL），不受分享設定變動影響，只要目前登入的使用者仍在授權名單內就能讀到
- **匯出快照時，這份在線明細資料量較大（22 萬筆）**：需確認現有 Apps Script 的單次
  上傳配額（`apps-script/README.md` 已知限制：目前快照約 30–40MB）夠不夠用，若超過
  需要壓縮或只存彙整後的平均值而非全部明細——實作時第一步就要驗證這件事

## 相依影響

- `js/auth.js`：新增 OAuth token client 邏輯＋背景換發計時器（現有 ID token 登入流程
  不變，兩者接在同一次使用者點擊）
- `js/sheets.js`：新增一個讀取這份新資料來源的函式（用 Sheets API，不是既有的 gviz
  CSV 讀法）
- `js/metrics.js`：新增「在線平均已使用年限」的計算函式（含日期 fallback／負值排除／
  分母為 0 的處理）
- `js/app.js`／KPI 卡呈現處：新增兩張卡片（車機/鏡頭），含篩選連動與載入失敗態
- `js/cloud.js` ＋ `apps-script/Code.gs`：擴充既有「匯出本期快照」，把這份在線明細也
  一併存進共用雲端硬碟；實作前先驗證資料量會不會超過現有上傳配額
- `設備品質分析_分冊文件/00_規則定義.md`：新增規則 H
- 不影響：現有規則 A–G、現有「已使用年限」（規則E）、`js/transform.js`、
  `js/report.js`（落地頁報告，這次不含）

## 驗收標準

- 登入後（第一次會多跳一次同意畫面，接在登入按鈕同一次點擊裡），KPI 卡區塊出現「在線
  平均已使用年限」，車機、鏡頭分別各顯示一個數字
- 依廠商/類型/ERP品號篩選後，兩個數字都會跟著重新計算
- 刻意讓授權失敗、或瀏覽器封鎖同意彈窗時，只有這兩張卡片顯示錯誤＋重試，其他 KPI、
  明細表、篩選功能都正常；重試需要使用者再點一次才觸發
- 缺進貨日/安裝日、或算出負值年限的記錄，不會讓平均值計算出錯、也不會讓整頁掛掉
- 篩選後沒有符合的設備，或設備都有但日期全部不可用，兩種情況都顯示空白/無資料，不顯示 0
- 按「📥 匯出本期快照」後，共用雲端硬碟裡的快照檔含這份在線明細資料
- `00_規則定義.md` 出現規則 H，且 `js/metrics.js` 對應計算函式的註解指向該規則
