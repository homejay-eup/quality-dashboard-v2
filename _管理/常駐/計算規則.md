# 計算規則（現行）

> 品質工具「應該怎麼算」的唯一書面依據，只寫**現在**的規則，不留舊版本（舊版看 git 歷史）。
> 內容已逐條對照程式碼核對（2026-11-05）。**改到計算方式時，這份要在同一次存檔一起改**；文件和程式不一致時，先停下來問使用者哪個才對。
> 規則字母 A–H 沿用以前的編號，程式碼註解用同樣的字母對應。

## 資料來源

| 資料 | 從哪來 | 用在哪 |
|---|---|---|
| 派工、回廠、維修、報廢、上線量 | Google Sheet「設備品質分析來源」的 SQL_ 分頁 | 全部計算 |
| 關鍵字對照表、類型清單、品號對照表 | 同一個 Sheet 的對照分頁（**規則的一部分放在這裡，改分頁內容就等於改規則**）| 規則 A、F |
| 年限門檻表 | 同一個 Sheet（**目前還沒建立**，所以一律用預設：車機 3 年、鏡頭 1 年、耗材不判定、其他 1 年）| 規則 C |
| 進貨日 | `js/data/purchase_dates.json`（由 `scripts/build_purchase_dates.py` 從「產品進貨單」條碼檔產生，同條碼取最舊日期）| 規則 E |
| 車機鏡頭上線明細 | 私有 Google Sheet，要使用者 Google 登入才讀得到 | 規則 H |

## 期間與分析範圍

- **期間是累積制**：Q1＝1–3 月、Q2＝1–6 月、Q3＝1–9 月、Q4＝1–12 月。
- **哪些派工算進本期**：派工的「品項完工日期」落在期間內。回廠、維修也只取期間內的紀錄（回廠看回廠時間，維修看輸入年月）；同一條碼有多筆時，取日期最接近完工日的那筆。報廢沒有日期，取該條碼的第一筆。
- **車機分頁**＝設備類型「車機」**且**維護原因「訊號異常」；**鏡頭分頁**＝設備類型「鏡頭」**且**維護原因「影像異常(鏡頭)」。不符合的派工不進任何一個分頁。
- **篩選**：廠商、類型（＝廠牌型號）、ERP品號三層，都沒勾＝不限制。

## 規則 A：維護類型（看「維護細節」）

照「關鍵字對照表」分頁，依優先序由小到大比對，維護細節**包含**該關鍵字就歸到對應的維護類型；都沒命中或空白＝「其他」。故障原因欄位：車機看 AB點／失聯／定位不良／訊號異常／其他，鏡頭看 黑畫面／進水/模糊／水波紋／時有時無／其他（「其他」＝回廠量減掉前四項）。

## 規則 B：維修分類（看「完成原因」）

依序比對，先命中先算：已完修 人為 → `V /已完修 人為`；已完修 → `X /已完修`；測試正常 → `O /測試正常`；過保報廢 → `E`；評估後退修 → `G`；停產報廢 → `D`；人為報廢 → `H`；不送修 → `不送修`；維修換貨 → `維修換貨＋換貨條碼`。空白或都沒命中＝「無維修資訊」。

## 規則 C：QC

依序判斷：
1. 維修分類 O → **廠商檢測正常**
2. X、V、維修換貨 → **廠商完修**
3. E、G、D、H → **廠商報廢**
4. 不送修、沒有報廢原因 → **回廠QC**
5. 無維修資訊或不送修、**有**報廢原因：已使用年限未滿門檻（車機 3 年、鏡頭 1 年）→ **其他(未過)**；否則 → **回廠報廢**
6. 其餘（無維修資訊、沒有報廢原因）→ **其他**

## 規則 F：設備類型、類型、廠商

用派工的「替換前品項」對「類型清單」取設備類型、廠牌型號（＝類型）、ERP品號、廠商；廠商空白時改用 ERP品號 對「品號對照表」的主供應商名稱；還是沒有＝「未分類」。上線量則用 ERP品號 對類型清單。**類型清單沒維護到的品號，不會算進車機或鏡頭分頁**（畫面上的「類型清單待補提醒」會列出來）。

## 規則 G：四桶（只算回廠的設備）

- **回廠量**＝回廠狀態有值且不是「無記錄」「不回廠」（已回廠、已遺失、已升級都算）。
- **良品**＝QC 是 廠商檢測正常、回廠QC、其他
- **不良品**＝維修分類是 G、X、維修換貨
- **過保**＝維修分類是 D、E，或 QC 是 回廠報廢
- **未歸類**＝以上都不是（實際上是 H 人為報廢、V 已完修人為、QC 其他(未過)）；**回廠狀態「已遺失」一律算未歸類**
- 四桶互斥，加總＝回廠量。

## KPI

| 指標 | 算法 |
|---|---|
| 總線上量 | 「上線量」分頁依 ERP品號 加總（同一 ERP品號 只取第一列）|
| 期間再使用率／不良率／過保率／未歸類率 | 良品／不良品／過保／未歸類 ÷ 回廠量（四個加總＝100%）|
| 整體不良率／整體過保率 | 不良品／過保 ÷ 總線上量 |
| 回廠過保數（規則 D，分析表欄位）| D＋E＋QC 回廠報廢（不含其他(未過)）|

## 規則 E：回廠年限（已使用年限）

- 單台：(品項完工日期 − 進貨日) ÷ 365，取 1 位小數；日期缺或算出負數＝不計。
- 進貨日：先查 `purchase_dates.json`，查不到依序用 派工 替換前進貨日 → 回廠 → 維修 → 報廢 的進貨日。
- 平均對象：**回廠**且屬於 不良品／過保／未歸類 的設備（良品不算）。可以和去年同期比。

## 規則 H：線上年限（在線平均已使用年限）

- 對象：「車機鏡頭上線明細」裡**所有**目前線上的設備，跟回廠無關；車機、鏡頭分開平均。
- 單台：(今天 − 參考日期) ÷ 365；參考日期先看「日期」欄，空白時看「日期依據」指定的進貨日或安裝日，再空白用另一個；都沒有或算出負數＝不計。平均後取 1 位小數，沒有任何可算的設備＝顯示「—」（不是 0）。
- 是「現在」的數字，不比去年同期。

## 待確認的口徑（使用者決定前維持現狀）

- 總線上量：「上線量」分頁同一 ERP品號 若有多列，目前只算第一列。
- 類型清單同一品名有多列時，只取第一列。
