# 功能規格範本

> ⚠️ 這是 `_管理/範本/` 裡的空白格式範本。每個功能在 `_管理/specs/` 建 `{功能名稱}.md`（如 `auth.md`），複製下方「規格骨架」填寫。

## `_管理/specs/` 裡每個功能有兩種檔（差在 `-設計` 尾綴）

| 檔名 | 是什麼 | 誰用 |
|---|---|---|
| `{功能名}.md` | **功能規格**——可逐條勾選的驗收條件、欄位、流程 | tester 逐條驗收、frontend／data 取規格 |
| `{功能名}-設計.md` | **設計文件**——`/brainstorming` 的決策脈絡 | 主 Agent 回顧決策；**不是** tester 的驗收依據 |

> 流程：`/brainstorming` → `{功能名}-設計.md` → 據此產出 `{功能名}.md` → 才派工。

---

## 規格骨架（複製這段到 `_管理/specs/{功能名}.md`）

```markdown
# {功能名稱} 規格

## 這個功能做完，你會看到什麼
<!-- 白話，給非技術者對焦。用「你／使用者」視角，2–4 句。
     不要出現檔名、型別、API、資料庫這些詞。 -->
（例：你在料卡列表頁按「批次匯入」，選一個 Excel 上傳。系統會比對現有料卡，
 分成「要新增的／要修改的／有衝突的」三區給你看；你勾選要匯入的，按確認才會寫進系統。
 衝突的不會自動幫你選。）

## 驗收條件
<!-- tester 依此逐條驗證，通過後存為腳本。每條寫「使用者做 X → 系統回應 Y」，
     非技術者也讀得懂。 -->
- [ ]（正常流程）使用者執行 X → 系統回應 Y
- [ ]（錯誤情境）輸入 Z → 顯示錯誤訊息 W
- [ ]（邊界條件）沒有資料／資料量很大／有重複值 時 → …
- [ ]（半途中斷）做到一半離開／重複送出 → …
```

## 使用時機

| 角色 | 時機 | 動作 |
|---|---|---|
| 主 Agent | 腦力激盪完、方案確認後 | 建立規格檔——先寫「你會看到什麼」＋驗收條件，再補開發區塊 |
| frontend agent | 執行前 | 讀規格確認 UI 細節 |
| data agent | 執行前 | 讀規格確認欄位與型別 |
| tester agent | 執行前 | 讀「## 驗收條件」節，逐條設計測試情境 |
