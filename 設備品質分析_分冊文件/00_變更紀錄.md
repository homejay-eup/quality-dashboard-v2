### 規則變更：三桶（良品/不良品/過保）改回窄口徑定義，H/V/其他(未過) 不進三桶

| 項目 | 說明 |
|------|------|
| 變更類型 | 規則變更（使用者裁決，非程式自行判斷） |
| 變更日期 | 2026-07-23 |
| 依據規則 | 使用者提供之原始三桶定義（取代 00_規則定義.md v5 §規則C 衍生出的「不良品=QC全口徑」版本） |
| 影響冊次 | 07（v2→v3，待建立） |
| 影響檔案 | `quality-dashboard-v2`：`js/transform.js`（`calcBuckets()`）、`js/metrics.js`（`aggregate()` 的「回廠過保數」欄、已使用年限平均計算） |
| 是否需重跑 | 否（Web 前端即時運算） |

**背景：**
使用者發現 Dashboard KPI 卡「良品數＋不良品數＋過保數」不等於「期間回廠量」，追查後發現目前程式（`calcBuckets()`）用的是 v5 QC 全口徑：「不良品＝QC∈{廠商報廢,廠商完修,回廠報廢,其他(未過)}」（含 D/E/G/H/V/換貨），「過保」是「不良品」的子集、非互斥。但使用者最初（本次對話開頭）提供的三桶定義是窄口徑、彼此互斥的版本，兩者並存於冊03 30欄彙整總覽（分別對應「回廠不良品數(全)」與「回廠不良品數」兩個不同欄位），KPI 卡片原本選了「全」口徑。

**使用者裁決（三桶改採窄口徑，互斥）：**
- 良品 = QC ∈ {廠商檢測正常, 回廠QC, 其他}
- 不良品 = 維修分類 ∈ {G /評估後退修, X /已完修, 維修換貨＋換貨條碼}（不含 D/E/H/V）
- 過保 = 維修分類 ∈ {D /停產報廢, E /過保報廢} 或 QC=回廠報廢（不含 QC=其他(未過)）
- 維修分類 H /人為報廢、V /已完修 人為、QC=其他(未過)：**三桶皆不計入**，比照回廠人為數獨立揭露，不視為資料異常
- 良品＋不良品＋過保 因此不等於期間回廠量，差額＝H＋V＋其他(未過)＋已遺失 筆數，為預期行為

**執行內容：**
1. `transform.js` `calcBuckets(QC, 維修分類Code)` 改寫為窄口徑互斥版本
2. `metrics.js` `aggregate()` 的「回廠過保數」欄拿掉 QC=其他(未過)（`d+e+qcScrap+qcOth2` → `d+e+qcScrap`），已使用年限平均計算的 `QC!=='其他(未過)'` 排除條件同步移除（因新版 過保 已不可能等於其他(未過)，屬冗餘判斷）
3. `aggregate()` 的「回廠不良品數(全)」欄**未變動**（仍是 D+E+G+H+X+V+換貨+回廠報廢+其他(未過) 的全口徑加總，用於「回廠不良品數(全)+回廠良品數＝回廠量」等式驗證，是跟 KPI「不良品數」不同用途的獨立指標，兩者並存不衝突）
4. node 單元測試驗證：G/X/換貨→不良品；D/E/回廠報廢→過保；H/V/其他(未過)→三桶皆 false；O/回廠QC/其他→良品，全部符合預期
