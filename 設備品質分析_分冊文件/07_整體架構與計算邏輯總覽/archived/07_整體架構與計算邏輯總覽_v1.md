## 1. 品質分析範圍

### 1.1 資料漏斗（期間內）

```
派工量  →  回廠量  →  維修量  →  報廢量
（cohort）  （已回廠子集） （送修子集） （報廢子集）
```

- **派工量**：期間內「品項完工日期」落在期間內的全部派工列（cohort），是所有後續計算的母體。
- **回廠量**：cohort 中實際回廠的子集（Web 版以「回廠狀態」欄位過濾，見 §10.2 差異說明）。
- **維修量／報廐量**：回廠子集中，進一步依「完成原因」「報廢原因」判斷出的維修分類與報廢狀態，非獨立的另一張表，而是同一批回廠明細依欄位判斷出的類別。

### 1.2 產品類別

| 類別 | 範圍界定（設備類型 + 維護原因） |
|------|-------------------------------|
| 車機 | 設備類型 = 車機 ／ 維護原因 = 訊號異常 |
| 鏡頭 | 設備類型 = 鏡頭 ／ 維護原因 = 影像異常(鏡頭) |

> 「維護原因」是派工來源欄位（非本系統判斷產生），用來把 cohort 縮小到「車機分析」或「鏡頭分析」兩個分頁各自的範圍。兩個分頁各自獨立計算彙整總覽／KPI／圖表，互不影響。

### 1.3 期間定義（季度累積制）

| 期間代碼 | 涵蓋月份 |
|---------|---------|
| Q1 | 1–3 月 |
| Q2 | 1–6 月 |
| Q3 | 1–9 月 |
| Q4 | 1–12 月 |

每年從 1 月重新累積，不跨年累積（例：2026-Q2 = 2026-01 ～ 2026-06，不含 2025 年資料）。

## 3. 明細建立流程（Step 1–8）

對應：冊01（Excel/Python）／ `build_分析總表.py build_detail()` ／ `transform.js buildDetail()`（三者邏輯一致）。

| Step | 內容 |
|------|------|
| Step 1 | **Cohort 篩選**：派工列「品項完工日期」落在期間內才留下 |
| Step 2 | **Join 維修**（同期，依條碼；避免跨期誤配）／**Join 報廢**（全量，報廐表無期間欄）／**Join 類型清單**（依替換前品項，取 ERP品號／設備類型／廠牌型號／廠商） |
| Step 2.5 | （僅正式 Excel 產出流程要求）ERP品號 對不上要先列出並等待使用者確認才可繼續產出；Web 版即時運算不阻斷，對不上分組的品項會被歸入「(未分類)」 |
| Step 2.7 | **廠商備援**（規則F）：類型清單查無廠商時，改用 ERP品號 查品號對照表.主供應商名稱 |
| Step 4 | **Join 上線量**：依 ERP品號 對應（單一時點快照） |
| Step 5 | **維護類型判斷**（規則A）：依「維護細節」關鍵字比對 |
| Step 6 | **維修分類判斷**（規則B）：依「完成原因」關鍵字比對 |
| Step 7 | **進貨日／已使用年限計算**（規則E） |
| Step 8 | **QC 判斷**（規則C）→ 三桶（良品／不良品／過保） |

|--------|----------|-----------|

| 2 | X /已完修 | 已完修 |
| 3 | O /測試正常 | 測試正常 |
| 4 | E /過保報廢 | 過保報廢 |
| 5 | G /評估後退修 | 評估後退修（或含「退修」） |
| 6 | D /停產報廢 | 停產報廢 |
| 7 | H /人為報廢 | 人為報廢 |
| 8 | 不送修 | 不送修 |
| 9 | 維修換貨＋換貨條碼 | 維修換貨（或「換貨條碼」） |

## 6. 判斷邏輯：規則 C — QC（現行 v5，依優先序判斷）

| 優先序 | QC 值 | 條件 |
|--------|-------|------|
| 1 | 廠商檢測正常 | 維修分類 = O /測試正常 |
| 2 | 廠商完修 | 維修分類 ∈ {X /已完修、V /已完修 人為、維修換貨＋換貨條碼} |
| 3 | 廠商報廢 | 維修分類 ∈ {E /過保報廢、G /評估後退修、D /停產報廢、H /人為報廢} |
| 4 | **其他(未過)** | 維修分類 ∈ {無維修資訊、不送修} 且 報廢原因不為空白 且 已使用年限 < 該設備類型年限門檻（鏡頭 1 年／車機 3 年） |
| 5 | 回廠報廢 | 維修分類 ∈ {無維修資訊、不送修} 且 報廢原因不為空白（且不符優先序4的年限條件） |
| 6 | 回廠QC | 維修分類 = 不送修 且 報廢原因為空白 |
| 7 | 其他 | 維修分類 = 無維修資訊 且 報廢原因為空白 |

> **v5 變更重點**：「不送修 + 有報廢原因」與「無維修資訊 + 有報廢原因」套用完全相同的報廢分支判斷（2026-07-17 決議）；v4 以前「回廠其他」已改名「其他(未過)」。

## 7. 三桶判斷（良品／不良品／過保）

| 桶 | 條件 |
|----|------|
| 良品 | QC ∈ {廠商檢測正常、回廠QC、其他} |
| 不良品 | QC ∈ {廠商報廢、廠商完修、回廠報廢、其他(未過)} |
| 過保 | 維修分類以 D 或 E 開頭，**或** QC ∈ {回廠報廢、其他(未過)} |

**特例（2026-07-17 決議）**：回廠狀態 = 已遺失 → 良品／不良品／過保三桶皆為 false（已遺失不等於可沿用，避免虛增再使用率），但**仍計入回廠量**。

良品與不良品互斥；過保是不良品的子集（過保數 ⊆ 不良品數，因 D/E 皆屬廠商報廢＝不良品，回廠報廢/其他(未過) 本身即為不良品分類）。

## 8. 規則 E — 已使用年限

- **單筆公式**：`(品項完工日期 − 進貨日) / 365`，取小數點第一位；任一日期缺失或差值為負（資料異常）→ null。
- **回廠過保數判斷**（規則D，v5）：符合任一條件即算回廠過保數：
  - 維修分類 = D /停產報廢
  - 維修分類 = E /過保報廢
  - QC = 回廠報廢
  - QC = 其他(未過)
- **彙整層級「已使用年限」**：對回廠過保數明細中**排除 QC=其他(未過)** 的記錄（即僅 D、E、回廠報廢 三類）取平均，取小數點第一位；無可用記錄 → 顯示空白。
  > 其他(未過) 雖歸屬回廠過保數欄位，但依 v5 規則明確排除在年限平均計算之外。

### 9.3 車機_月趨勢 ／ 鏡頭_月趨勢（依 ERP品號 × 年月 分組，16 欄）

**用途**：月粒度資料，供 Dashboard 畫「每月回廠量／不良品數」趨勢折線圖。

| 過保數 | 維修分類以 D、E 開頭，或 QC = 回廠報廢 的筆數（**Web 版另納入 QC=其他(未過)**，見下方說明） |
| 故障原因 5 欄 | 同 §4，最後一欄為餘數「其他」 |

> **月趨勢「不良品數／過保數」與彙整總覽「回廠不良品數／回廠過保數」定義不同**：月趨勢的「不良品數」只算 G/X/換貨（不含 D/E/H），刻意與彙整總覽的「回廠不良品數(全)」（含 D/E/H/V/其他未過）區分，避免同名不同義誤用。
>
> 冊05 文件字面公式的「過保數」未提及 QC=其他(未過)（該值是 v5 後補的 QC 分類，冊05 文件當時未跟著更新）；為與彙整總覽的「回廠過保數」邏輯一致，程式實作上一併納入其他(未過)。若日後需嚴格照冊05字面公式，需再確認是否移除。

## 10. 各項比率（KPI）計算邏輯

### 10.1 兩種分母：期間率 vs 整體率

| 比率 | 分子 | 分母 | 意義 |
|------|------|------|------|
| 再使用率 | 良品數 | 回廠量 | 回廠品項中，可繼續使用的比例 |
| 不良率（期間） | 不良品數 | 回廠量 | 回廠品項中，判定不良的比例 |
| 過保率（期間） | 過保數 | 回廠量 | 回廠品項中，過保的比例 |
| 整體不良率 | 不良品數 | 上線量（總線上量） | 不良品數佔全部在線設備的比例（母體更大，數值通常遠低於期間不良率） |
| 整體過保率 | 過保數 | 上線量（總線上量） | 過保數佔全部在線設備的比例 |

> **分母為 0 的處理**（`safeDiv`）：回廠量或上線量為 0 或未定義時，比率一律回傳 0（不會拋錯或顯示 NaN）。

### 10.2 KPI 卡片（落地頁／Dashboard 頂部）

| KPI | 定義 |
|-----|------|
| 總線上量 | 篩選範圍內上線量加總 |
| 期間回廠量 | isReturned 子集筆數 |
| 期間再使用率 | 良品數 / 期間回廠量 |
| 期間不良率 | 不良品數 / 期間回廠量 |
| 整體不良率 | 不良品數 / 總線上量 |
| 整體過保率 | 過保數 / 總線上量 |

同期比較（YoY）：以上每個 KPI 各自對當期、比較期分別計算，前端顯示差值（▲/▼ 百分點或數值）。

## 11. Excel/Python 流程（冊01–06）與 Web Dashboard（新版儀表板）：對應與已知差異

| 項目 | Excel／Python（冊01–06、build_分析總表.py） | Web Dashboard（quality-dashboard-v2） |
|------|----------------------------------------------|------------------------------------------|
| 資料源 | `.xlsm` 資料庫檔／`gsheet_source.xlsx` 快照 | 直連 Google Sheet（gviz csv，即時） |
| 輸出形式 | `.xlsx` 多工作表檔案 | 網頁畫面即時渲染 + 可匯出落地頁 HTML |
| 「回廠量」定義 | cohort 本身即代表回廠事件，**不另外過濾**，回廠量 = 該 ERP品號分組筆數 | 額外 join「回廠」表取得「回廠狀態」，回廠量 = isReturned（回廠狀態 非「無記錄」且非「不回廠」）子集筆數 |
| 已遺失特例 | 無此欄位／未特別處理 | 回廠狀態=已遺失 → 良品/不良品/過保三桶皆 false，但仍計入回廠量 |

> **已知差異的影響評估**：若某 ERP品號的 cohort 派工列，在「回廠」來源表中查無對應記錄或明確標記「不回廠」，Python 版仍會把它算進回廠量／各項計數，Web 版則不會。目前尚未實測兩版本在同一期間的回廠量是否有實質數字落差；若要合併使用兩版本數字，建議先跑一次同期同範圍的交叉比對。
>
> **2026-07-22 決議**：兩版本各做一版看結果，再決定以哪個為主；**目前暫時以 Excel 版為主**。待實測比對後回頭更新本節與 00_規則定義.md。

其餘規則 A–F、QC 判斷、三桶邏輯、已使用年限公式，兩版本程式碼**邏輯完全一致**（本冊撰寫時已逐一比對 `classify維護類型`／`classify維修分類`／`classifyQC`／`calcBuckets` 與 python 對應函式，無差異）。
