### 如何確認「腳本邏輯是否跟文件相符」

1. **先看版本號**：`build_分析總表.py` 檔案開頭的 docstring 有一個版本標記區塊，寫明目前對應 `00_規則定義.md`／`03_分析總表_工作表規格` 的版本號，執行時 `main()` 也會把這行印在終端機第一行。
2. **版本號只是宣告，不是保證**：如同 2026-07-24 發現的狀況（冊03 v6 掛了兩個月沒同步），版本號要靠人工維護，可能跟實際程式碼脫節。真正要確認一致，還是要直接讀程式碼比對規則文件，或看下一點的自動等式驗證。
3. **等式驗證（跑一次就知道有沒有漏改）**：`build_分析總表.py` 執行時會自動印出「等式驗證失敗」警告（若有）：
   - `回廠不良品數(全) + 回廠良品數 = 回廠量`（良品 vs 非良品 二分口徑）
   - `回廠良品數 + 回廠不良品數 + 回廠過保數 + 未歸類數 = 回廠量`（規則G 四桶口徑，v8 起新增）
   - 若這兩條驗證都沒印警告，代表當次執行的分類邏輯至少內部一致；但**不保證**跟 00_規則定義.md 的文字定義完全相符（例如某個 QC 值的判斷條件本身寫錯，等式仍可能恰好成立）——最終仍需要人工核對規則文字與程式碼。
4. **07冊是核對的起點**：`07_整體架構與計算邏輯總覽`（現行 v5）是唯一一份「明確標注逐行核對過原始碼」的文件，每次規則變更都會回頭在這份文件核對並記錄，是檢查「文件說的」跟「程式碼做的」是否一致時，最該先看的地方。

### 資料庫工作表清單

| Sheet Index | 工作表名稱 | 用途 |
|-------------|-----------|------|
| 0 | 上線量(PQ) | 統計各 ERP品號 上線數量 |
| 1 | 派工量(PQ) | 主表，提供品項完工日期、替換前品項、條碼等 |
| 2 | 維修量(PQ) | 提供維修資訊（完成原因）；以條碼 merge |
| 3 | 報廢量(PQ) | 提供報廢資訊（報廢狀態、報廢原因）；以條碼 merge |
| 4 | 進貨日(PQ) | 提供首次出現時間（進貨日）；以條碼 merge |
| 5 | 類型清單 | 提供 ERP品號、設備類型、廠牌型號；以替換前品項 merge |
